# Phase 0 Visual Baseline

Status: **INPUT SET FROZEN / VISUAL EXECUTION PENDING**

Date: 2026-09-09

This document defines the fixed visual baseline set used to compare the existing `md3-product-image` workflow with later Images 2.5 changes.

The baseline is intentionally split into two states:

1. **input baseline** — deterministic source files, hashes, metadata, and scoring rows are frozen now;
2. **visual baseline** — generated MASTER/SKU backgrounds and final composites are recorded only when the runtime can reliably bind the intended reference images.

No generated image is accepted into the baseline merely because it visually resembles the requested test case.

## 3. MASTER/SKU pairing rule

Within each fixture pair:

- MASTER and SKU use the same source canvas;
- MASTER and SKU use exactly the same alpha mask;
- MASTER and SKU use exactly the same geometry;
- only deterministic palette values differ.

This is deliberate.

The SKU baseline is intended to measure background palette adaptation and composition consistency without introducing product-shape changes as a confounder.

If the SKU background moves, adds, removes, or resizes scene geometry, that drift cannot be attributed to a changed product silhouette in this test set.

## 4. Evaluation rows

`docs/phase-0/evaluation-results.csv` contains exactly 14 baseline rows:

- 7 MASTER rows
- 7 SKU rows

Every row is already bound to:

- fixture id,
- run type,
- frozen production baseline commit,
- exact MASTER or SKU product SHA-256.

Generated-image hashes, prompt hashes, output dimensions, final-composite hashes, and visual scores remain empty until a valid visual run exists.

---

## 5. Valid MASTER baseline run

For each fixture, a MASTER run is valid only if all of the following are true:

1. the exact `*-master.png` source from the manifest is supplied as the product palette reference;
2. the exact `baseline-logo.png` is used for local deterministic composition;
3. the existing baseline `references/image-gen-prompt.txt` is used without Images 2.5 prompt restructuring;
4. `scene_prompt.py` builds and records the actual prompt;
5. only one image-generation operation is used for the attempt;
6. the returned background is saved unchanged before local composition;
7. the normal local product / shadow / Logo / text composition path is used;
8. the final candidate is recorded without automatic aesthetic retry;
9. prompt, background, and final-composite SHA-256 values are recorded in the CSV.

The baseline MASTER does not need to be aesthetically perfect. It needs to be a faithful sample of the current workflow.

---

## 6. Valid SKU baseline run

A SKU row is valid only after the corresponding MASTER has been generated and locked for that fixture.

The current baseline SKU behavior must be preserved:

- locked `ORIGINAL_MASTER_BACKGROUND.png` is the composition reference;
- the exact paired `*-sku.png` is the current SKU palette reference;
- `references/replace-variant-block.md` remains the current baseline instruction;
- the model generates a new empty background rather than using a future constrained-edit implementation;
- local deterministic composition creates the final SKU image;
- background and final-composite hashes are recorded.

The SKU baseline must not silently use a future palette-only reference or a future image-edit path.

---

## 7. Visual scoring

Scores are entered only after the final visual is inspected.

Use an integer `1–5` scale where applicable:

- `1` = materially poor / clear failure
- `2` = weak
- `3` = acceptable baseline
- `4` = good
- `5` = very strong

The baseline table tracks:

- `background_quality`
- `classic_md3_adherence`
- `palette_harmony`
- `safe_zone_cleanliness`
- `sku_composition_consistency`
- `unwanted_product_copying`
- `product_like_geometry`
- `accidental_text_or_logo`
- `unexpected_physical_environment`

For negative metrics (`unwanted_product_copying`, `product_like_geometry`, `accidental_text_or_logo`, `unexpected_physical_environment`), use:

- `1` = none observed
- `2` = minor
- `3` = noticeable
- `4` = significant
- `5` = severe

This direction must remain unchanged in later ablations.
